# GAIJIN SUSHI — электронное меню

React + TypeScript + Vite + Tailwind CSS + Zustand + React Router + Lucide.

## Запуск сайта

```bash
npm install
npm run dev        # frontend only: http://localhost:5173
npm run dev:all    # frontend and API together, after database setup
npm run build      # production-сборка в папку dist
npm run preview    # просмотр production-сборки
```

Нужен Node.js 18+.

## Админ-панель и база данных

Изменения меню сохраняются в PostgreSQL и доступны всем посетителям. Для локального запуска нужны Node.js 18+, PostgreSQL и Docker Compose (или установленный PostgreSQL).

1. Создайте `server/.env` из `server/.env.example` и проверьте `DATABASE_URL`.
2. Запустите PostgreSQL. Если установлен Docker Compose:

   ```bash
   cd server
   docker compose up -d postgres
   ```

3. В `server/.env` задайте `ADMIN_USERNAME` и `ADMIN_PASSWORD` (не менее 12 символов). Не публикуйте этот файл.
4. Установите зависимости, создайте таблицы, загрузите исходный каталог и создайте администратора:

   ```bash
   cd server
   npm install
   npm run db:migrate
   npm run db:seed
   npm run admin:create
   ```

   `db:seed` добавляет начальные блюда только один раз и не перезаписывает изменения в базе.
5. После настройки базы и администратора запустите API и сайт одной командой из корневой папки проекта:

   ```bash
   npm run dev:all
   ```

   Если нужно запускать процессы отдельно, используйте `cd server && npm run dev` и `npm run dev`
   в двух терминалах.

Откройте [http://localhost:5173/admin](http://localhost:5173/admin) и войдите с заданными логином и паролем. В админке можно добавлять, редактировать, скрывать и удалять блюда и категории, менять цены и изображения, а также отмечать блюдо как временно недоступное. В меню посетителю покажется статус; нажатие на такую позицию покажет уведомление, что блюда пока нет.

Без запущенного API сайт временно показывает исходное меню и предупреждение, что данные не удалось обновить. Для публикации настройте проксирование `/api` на сервер и укажите адрес сайта в `FRONTEND_ORIGIN`.

## Как это работает

1. Гость открывает сайт (можно по QR-коду) и листает меню по категориям.
2. Кнопка «+» на фото добавляет блюдо, потом появляется счётчик «− 1 +». Нажатие на фото — карточка блюда с описанием.
3. Корзина (кнопка в шапке или красная панель внизу): количество, удаление, очистка, итог.
4. «Показать заказ кассиру» → чек с номером, датой, составом и суммой. Кнопка «Показать кассиру» открывает крупный экран, есть увеличение текста и печать/PDF.

Онлайн-оплаты нет, заказ автоматически никуда не отправляется — чек показывают на кассе.
Тема (светлая/тёмная), язык (RU/EN), корзина и чек сохраняются в localStorage.

## Начальные данные меню

Начальный каталог хранится в `src/data/menu.ts` и загружается в PostgreSQL командой `npm run db:seed`:

- **Категории** — массив `CATEGORIES` (id + названия RU/EN).
- **Блюда** — массив `PRODUCTS`: название, описание (RU/EN), цена в сомах, категория и фото.
- **Фото** кладите в `public/menu/` и указывайте имя файла в `img('имя-без-.jpg')`.

Контакты (телефон, адрес, часы работы) — в `src/data/info.ts`. Пустые поля на сайте не показываются.
Переводы интерфейса — `src/i18n/translations.ts`.

Текущие блюда и категории после загрузки редактируются через `/admin`, а не через файл исходных данных.
В админке фото можно загрузить с устройства или указать ссылку; загруженные фото хранятся в PostgreSQL,
чтобы не пропадать после перезапуска или деплоя сервера.

## Публикация

### Подготовка GitHub

GitHub хранит исходный код, но не запускает этот API и не предоставляет PostgreSQL. Не добавляйте
в репозиторий `server/.env`: в нём находятся пароль администратора и параметры подключения к базе.
Для локальной конфигурации используйте `server/.env.example` как шаблон и задайте собственные
значения. Если реальные секреты уже попадали в публичный репозиторий, смените их.

Для этой папки уже создан отдельный локальный Git-репозиторий. Создайте на GitHub пустой репозиторий
(без README, `.gitignore` и лицензии), затем из папки проекта выполните:

```bash
git add .
git status --short
```

Если вы распаковали исходники заново и у папки ещё нет `.git`, сначала выполните `git init -b main`.
Перед коммитом убедитесь, что в списке нет `.env`, `node_modules` или других локальных файлов.
Затем подставьте URL созданного репозитория:

```bash
git commit -m "Prepare Gaijin Sushi menu"
git remote add origin https://github.com/<ваш-логин>/<имя-репозитория>.git
git push -u origin main
```

GitHub Actions автоматически проверит сборку сайта и API при push и создании pull request.

### Развёртывание сайта и API

`npm run build` собирает сайт в `dist/`. Фронтенд можно разместить на Vercel; `vercel.json`
направляет `/api` на настроенный Render API. GitHub Pages для этой конфигурации не подходит без
отдельного API-хостинга и настройки прокси.

Для полноценной работы админки и обновляемого меню отдельно разверните API и PostgreSQL. При
развёртывании API задайте переменные окружения `DATABASE_URL`, `ADMIN_USERNAME`,
`ADMIN_PASSWORD` (не менее 12 символов), `FRONTEND_ORIGIN` и `NODE_ENV=production`.
Для текущего сайта используйте `FRONTEND_ORIGIN=https://gaijin-sushi-ivanovka-pex1.vercel.app`;
добавляйте дополнительные origin через запятую. Не используйте локальные пароли из примеров в production.
Примените миграции командой `cd server && npx prisma migrate deploy`, создайте администратора
`cd server && npm run admin:create`, затем соберите и запустите API командами
`npm run build` и `npm start` из папки `server`.

Для Netlify или Cloudflare Pages настройте аналогичные SPA-переадресацию и проксирование `/api`
на ваш API. Без доступного API сайт покажет исходное меню и предупреждение об ошибке обновления.
